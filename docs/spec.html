ロジトレ 設計仕様書

v1.0 時点の設計をまとめたもの。開発を引き継ぐ人(Claude Code を含む)向け。利用者向けの説明は取扱説明書(manual.html)を参照。

1. 概要

ロジカルシンキングの「思考ノート」と「ドリル」を1つにした PWA(ブラウザで動き、インストールしてアプリのように使える Web アプリ)。

  • 利用者:本人1人。ログインなし
  • 端末:Android スマホと PC(Chrome / Edge)
  • 公開先:GitHub Pages https://tmgalaxy330-byte.github.io/PWA-app/(公開リポジトリの main 直下を配信)

2. 前提と方針

  • データは端末内だけ:localStorage(ブラウザ内の保存領域)に保存し、サーバーには送らない。端末間の移動は「書き出し/読み込み」(JSON ファイル)。
  • ビルド不要:HTML/CSS/JS を index.html 1ファイルにまとめる。外部ライブラリ・外部通信なし。
  • オフライン対応:Service Worker がファイルをキャッシュし、電波がなくても動く。
  • 日本語入力:Enter の判定では e.isComposing と keyCode===229 を必ず除外する(変換確定の Enter を誤検知しないため)。
  • 保存:モバイルでは終了イベントが来ないことがあるため、入力後の自動保存と visibilitychange(画面が隠れたとき)で保存する。

4. index.html の構成

スクリプトは /* ===== 見出し ===== */ で区切っている。主な部品:

  • APP:名前・版(version)・保存キー(logitore.v1)
  • Store / migrate():読み込み・保存・旧データの移行
  • エラーログ、演出(リップル・シェイク・紙吹雪)、トースト(画面下の短いお知らせ)
  • Back(シート等の重なりを閉じる)と Nav(画面の移動)
  • オーバーレイ部品:sheet() dialog() menu()
  • テーマ、テンプレート(TPL USAGE SAMPLE DIAG)、用語集(GLOSS)
  • 画面:renderHome / renderEditor / ドリル(Q 20問)/ ゴミ箱 / 設定
  • 書き出し・読み込み、PIN ロック、初回ガイド、更新通知、起動(boot)

5. データ形式

S = { schema, thoughts[], trash[], settings{}, drill{}, errors[], meta{} }

思考  { id, title, template, status(draft|wip|done), pinned, created, updated,
        root(ノードの木), memo, mece{a,b,c}, reviews[] }
ノード { id, text, children[], label, ph, collapsed }
  • 保存キー:localStorage["logitore.v1"]
  • 形式を変えるときは migrate() に移行処理を書き、既存データを壊さない(例:旧 tree テンプレートは why に自動移行)
  • 書き出しファイル:logitore_backup_YYYYMMDD_HHMM.json(thoughts / trash / drill を含む)。読み込みは「統合」と「上書き」を選べる
  • ゴミ箱は30日で自動削除。何も入力せずに離れた思考は自動削除

6. 画面と機能

ホーム

  • 思考の一覧(番号・タイトル・状態・型・更新日)、絞り込み(すべて/下書き/検討中/完了)、並び替え、ピン留め、全文検索
  • スワイプで複製/削除(画面の端28pxから始めた操作は無視)、長押しメニュー
  • お知らせ行(前回までのエラー件数・書き出しの催促)、今日のドリルの進み具合、＋で新規作成

6-1. テンプレート(6種類)

キー名前構成
whyWhyツリー問題 → 原因 → 深い原因
howHowツリー目的 → 手段 → 具体策
pyramidピラミッド結論 → 理由 → 根拠
sky空・雨・傘テーマ → 空(事実)/雨(解釈)/傘(行動)
prosメリデメ比較比較テーマ → 選択肢(2つ以上)→ メリット/デメリット → 内容
blank白紙テーマ → 項目

各テンプレートに使い方(目的/手順/記入例/よくある失敗/次にやること)、ビジネス向けサンプル(架空の数値と明示)、「迷ったら診断」(1〜2問で型をすすめる)。

6-2. 作業画面

  • アウトライン表示(編集用)とツリー表示(全体確認・拡大縮小)
  • 操作バー:下に追加・同階層・右へ・左へ・上へ・下へ・削除。⋮⋮ でメニュー/ドラッグ並べ替え
  • キーボード:Enter Tab Shift+Tab Alt+↑↓ Ctrl+Z Ctrl+Y
  • 元に戻す/やり直す(アプリを閉じると履歴は消える)、自動保存と保存状態の表示
  • プロパティパネル(スマホは下からのシート、PC は右側で折りたたみ可):状態、MECE チェック+自動チェック、メモ、AI レビュー履歴、情報
  • AI に提出:依頼文(厳しめ/やさしめ/MECE 確認/反論)+ Markdown をコピー・共有。返答を貼り付けて保存
  • 集中モード、画像(PNG)書き出し

6-3. ドリル

  • 1日5問(日付で出題を固定)、途中から再開、不正解でシェイク、3問以上正解で紙吹雪
  • 連続日数、正答率、直近14日のグラフ、「もっと練習する」

その他

  • ゴミ箱、PIN ロック(起動時と1分以上離れたとき)、エラーログ(次回起動時にお知らせ)
  • 初回ガイド3枚、用語集、取扱説明書、更新通知、共有ターゲット(他アプリからの共有で新規作成)

7. 戻る操作

状態戻る
シート・メニュー・確認画面閉じるだけ
作業画面1回目は「もう一度でホームへ」、3秒以内の2回目で戻る
ドリル・設定・ゴミ箱ホームへ
ホーム1回目は「もう一度で終了」、2回目で終了

設定でオフにできる。Android は CloseWatcher、それ以外は History API を使う。自動テストでは Esc キーで代用しており、実機での確認が必要。

8. 見た目(デザイン)

  • 基本は落ち着いたグレーの背景+白(ダークでは濃いグレー)のカード、アクセント1色(青・緑・橙から選択)
  • 番号・型名・日時は等幅フォント
  • テーマ:ライト/ダーク/端末に合わせる。文字サイズ4段階、動きを減らす
色の名前用途ライトダーク
--bg背景#ECEEF2#1A1C21
--bg2カード・上部バー#FFFFFF#24272D
--bg3押したとき・入力中#F3F4F7#2D3038
--tx文字#262A31#DDE0E6
--sub補足の文字#6A717E#959BA7
--ln / --ln2線・枠#E0E3E8 / #C8CDD5#32363E / #454A54
  • 枠:角丸10px・線1px。上部バーは画面幅いっぱいの背景+下線
  • PC の表示幅は最大900px(作業画面は1240px)
  • theme-color(インストール時のタイトルバー色)は上部バーと同じ色

9. PWA・更新・公開

  • Service Worker はキャッシュ優先(キャッシュにあればそれを使い、なければネットから取得)
  • 更新の届き方:sw.js の CACHE 名が変わると、端末が新しい版を検知してアプリに「更新があります」を出す。CACHE 名を変えないと更新が届かない
  • インストールできるのは https://(または localhost)から開いた場合だけ。file://(ファイルを直接開く)ではインストールできない
  • 公開:GitHub Pages(Source = main / root)。main に取り込むと数十秒〜数分で自動公開される
  • 公開されるのはプログラムだけで、利用者のデータは含まれない。なお、データはサイトのアドレスごとに分かれて保存されるので、アドレスが変わると「書き出し→読み込み」が必要

10. テスト

  • bash tests/run.sh:簡易サーバーを起動して3種類のテストを実行(スマホ表示・PC 表示・テンプレート)
  • 必要なもの:Python 版 Playwright(pip install playwright)と Chromium。既存の Chrome を使う場合は CHROME_PATH で場所を指定
  • 出力の errors 1 はエラーログ機能の確認のために意図的に起こしたもの。合否は最後の ALL TESTS PASSED とコンソールエラー一覧(ERRORS: [])で判断する

11. 開発と記録の手順

  • 実装はユーザーが「実行」と言ってから。見た目の変更は先に試作(モック)を見せて確認を取る
  • 「記録」前の実装は「試作(trial-N)」。「記録」で正式な版を付ける(通常の追加・修正はマイナー v1.0→v1.1、大きな変更はメジャー v2.0)
  • 記録のときにやること:APP.version と CACHE 名を更新 → 取扱説明書とこの仕様書の更新履歴に追記 → docs/handoff/handoff_vX.Y.md を新規作成 → main に取り込み、vX.Y のタグを付ける
  • 作業はブランチで行い、PR を作ってから main に取り込む

12. 未実装・既知の制限

次に実装する:複数タブの自動読み直し(採用済み)

  • 背景:PC で2つのタブを開くと、後から保存したタブの内容で上書きされる
  • 仕様:storage イベントで別タブの変更を検知 → 未保存の変更があれば先に保存 → S を読み直して画面を描き直す → トーストで知らせる。開いていた思考が消えていたらホームへ戻る
  • 受け入れ条件:タブAで追加した思考がタブBに数秒以内に表示される/タブBで編集して閉じてもタブAの思考が消えない/既存テストがすべて成功

既知の制限

  • Android の戻るボタンは実機で未確認
  • 会社の PC など、管理者の設定によってはインストールの表示が出ない場合がある
